# 문제 정의서 — 검토용 초안

> 강의 4 산출물. 근거 정본: [인터뷰·관찰 기록](research/interviews.md). 아래에는 현재 정한 문제 판정 기준과 두 단계 검수 목표를 반영했다. 제품 검수 결과는 아직 없다.

## 1. 한 문장 문제

수학 연계문항을 직접 제작·검토하는 강사와 문항 제작자가 **원문의 핵심 풀이 의도를 유지하면서 조건과 풀이의 성립을 한 번에 확인하기 어려워**, 후보 문항의 조건 수정과 재검토를 반복한다. (로그 1, 2, 3, 4, 6, 7, 8, 10)

## 2. 대상과 비대상

- **1차 사용자:** 원본문항을 바탕으로 연계문항을 만들거나, 후보 문항의 풀이와 조건을 직접 검토하는 수학 문항 제작자 및 학원 수학 강사. (로그 1~10)
- **현재 비대상:** 문항을 풀기만 하는 학생, 비수학 문항 제작자, 문항 판매·정산 담당자.

## 3. 증거

| 관찰된 문제 | 인터뷰 근거 |
|---|---|
| 조건·풀이 수정 또는 재검토에 추가 작업이 든다. | 인터뷰 10건 중 7건(로그 1, 3, 4, 5, 6, 7, 8) |
| 하나의 조건을 고친 뒤 다른 경계나 풀이 경로를 재확인한다. | 오류 수정의 연쇄(로그 1), 극점·상수항 조건의 재검토(로그 3), 0에서의 분기 재검토(로그 8) |
| 풀이 의도를 살리려다 조건 부족 또는 의도하지 않은 풀이를 발견한다. | 의도치 않은 풀이로 조건 수정(로그 2), 누적 오차의 한쪽 경계 누락(로그 4), 정의역·역함수 조건 추가(로그 7) |
| 문항 자체의 성립과 수업·회차에 맞는지의 판단이 다르다. | 회차 적합성과 학생 검증 부재(로그 5), 수업 범위에 맞춘 풀이 조정(로그 9) |
| 표현을 바꾸는 과정에서 대상의 존재 조건도 무너질 수 있다. | 삼각형 성립 실패 사례(로그 10). 최종 폐기 판정까지 추론하지 않는다. |

검수 장부의 판정은 [관찰 1](research/interviews.md#c-워크플로-관찰-기록)의 **별도 작업물 근거**다. 인터뷰 응답자의 작업 과정과 동일하다고 간주하지 않는다.

## 4. 반증 조건

### 문제의 실재 — 확보한 인터뷰 로그로 판정

- **주장:** 수학 연계문항을 만드는 제작자·강사는 원문의 풀이 의도를 지키면서 조건과 풀이의 성립을 확인하는 과정에서 수정·재검토에 추가 작업을 쓴다.
- **반증 조건:** 인터뷰한 대상 사용자 10명 중 실제 수학 연계문항 제작·검토 과정에서 조건·풀이 수정 또는 재검토에 추가 작업을 쓴 사람이 **3명 미만**이면 문제 정의를 기각하고 대상 또는 문제 문장을 다시 쓴다.

### 해결 가설 — 제품 사용 관찰로 이후 판정

- **가설:** 원문과 해설에서 핵심 풀이 요소 두 가지와 두 요소의 연결 메커니즘을 찾아 이를 응용하고, 수치·기호만 바꾼 수준을 넘는 수학적으로 성립하는 후보와 검토 근거를 제공하면 제작자는 큰 재설계 없이 강사가 사용할 만한 연계문항을 얻는다.
- **반증 조건:** 1차 기준을 통과하고 강사의 독립 풀이에서 수학적 성립과 수업 범위까지 확인된 후보를 받았는데도, 강사가 **그 후보 중 70% 미만**을 사용 가능으로 판정하고 나머지에서 원문의 풀이 의도 훼손이나 직접 다시 설계해야 하는 부담을 이유로 든다면 이 가설을 기각한다.
- 1차 통과율이 70% 미만이거나 강사 검수에서 수학적 오류·교육과정 이탈이 새로 발견되면, 가설 자체보다 **후보 생성·검증 품질의 실패**로 따로 기록한다. 가설을 판단할 적합 후보가 없으면 가설 판정은 보류한다. 두 단계의 원자료와 탈락 이유를 모두 남긴다.

## 5. 성공의 정의

- **1차 통과율 = 개발자 통과 후보 수 / 생성한 전체 평가 후보 수. 목표 70% 이상.** 평가할 문항 묶음을 사전에 정하고 생성된 후보를 빠짐없이 평가한다. 개발자는 원문과 비교해 (1) 수치·기호만 바꾼 문항이 아닌지, (2) 두 핵심 풀이 요소의 연결 메커니즘을 제대로 응용했는지, (3) 조건과 풀이가 기본적으로 성립하는지를 검토한다. 세 항목을 모두 충족해야 통과한다. 묶음의 1차 통과율이 70% 미만이면 강사 평가로 넘기지 않는다.
- **2차 통과율 = 수학 강사 통과 후보 수 / 강사에게 전달한 1차 통과 후보 수. 목표 70% 이상.** 강사는 독립적으로 풀고 수학적 성립, 풀이 의도, 수업 범위와 사용 가능성을 판단한다. 강사가 해당 문항을 사용 가능하다고 최종 승인하면 통과로 세고, 승인하지 않으면 이유를 기록한다.
- **전체 최종 통과율 = 수학 강사 통과 후보 수 / 생성한 전체 평가 후보 수.** 1·2차 비율과 함께 공개하여 1차 선별 효과를 숨기지 않는다. 후보 1건당 수정 횟수와 검토 시간도 개선 방향을 판단하는 보조 지표로 기록한다.
- 두 단계의 분모는 다르다. 예를 들어 후보 10건 중 1차에서 7건, 그중 2차에서 5건이 통과하면 각 단계의 목표는 충족하지만 전체 최종 통과는 5건이다.
- 두 단계에서 70%에 못 미치면 실패 유형을 기록하고 검색 자료·문서·프롬프트 등의 개선을 검토한다. 개선 후에는 사용했던 평가 문항만 반복하지 않고 새 평가 문항으로 다시 측정한다. RAG 채택 여부와 구체적 생성 방식은 후속 설계에서 정한다.

현재 1절의 문제 문장에는 **반복 수정·재검토**가 포함돼 있다. 이를 실제로 줄였다고 주장하려면 기존 제작 방식과 수정 횟수·검토 시간을 비교해야 한다. 그 비교를 하지 않는다면 이번 70% 검수 결과로 말할 수 있는 것은 **검수에서 통과하는 연계문항의 비율**까지다.
